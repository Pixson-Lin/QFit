# QFit — 安裝／使用次數可見性

| Field | Value |

## 問題

在目前 QFit 設計（無登入、不蒐集 email、本機寫入 Health Connect、不上傳帳號）下，**有沒有任何方法可以確認 QFit 被安裝或使用的次數？**

## 簡答

**就 App 本身與目前設計而言：沒有。**  
開發者收不到「誰安裝了／用了幾次」的訊號。

Health Connect 寫入只發生在使用者手機上；Google Sign-In、後端、分析 SDK 都不在設計裡，因此沒有回報通路。

## 分層說明

| 來源 | 能否知道安裝／使用？ | 說明 |
|---|---|---|
| QFit App（目前設計） | **否** | 不登入、不打自家伺服器、不送事件 |
| Health Connect | **否** | HC 不通知開發者；寫入是裝置端權限資料交換 |
| Sideload 發 APK | **否**（自動） | 除非使用者主動回報，否則開發者看不到安裝數 |
| Play Console 彙總數據 | **有限、匿名、且僅在上架 Play 時** | 商店側的安裝／活躍裝置等**彙總**統計；不是「使用者把 email 給你」，也看不到個人身分 |
| 之後若加入遙測／後端 | 可以，但會改變設計 | 需另做產品／隱私決策；與「避免把帳號給開發者」的定位要分開講清楚 |

## 與「不要 email」的關係

- **Play Console 彙總統計** ≠ 使用者把 Google account 交給開發者。那是商店後台的匿名／彙總指標。
- **Internal testing 邀請名單** 才是「開發者持有試用者 email」；目前 QFit 刻意避開這條路。
- 若堅持「App 零回報、也不上 Play」，則安裝／使用次數在設計上就是不可見的。

## 若未來需要「大概知道有沒有人在用」

在不收回登入的前提下，常見選項（皆需另開決策，**不是**現況）：

1. **上架 Play（Open testing / Production）** — 用 Console 彙總數據看趨勢。
2. **選擇性、可關閉的匿名事件**（例如「完成一次寫入」心跳到自有後端）— 要寫進隱私政策，且不能綁 Google 帳號。
3. **請使用者自願回報**（表單、聊天室）— 人工、不可擴。

在「維持現在這套零登入、零回報」的前提下：**沒有方法確認安裝或使用次數。**
